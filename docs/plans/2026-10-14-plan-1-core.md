# spring-ai-insights — Plan 1: Core capture Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Spring Boot starter that, with one dependency, records every Spring AI conversation
turn (identity, tokens, cost, tool calls, retrievals, latency, time to first token) into an
in-memory store and Micrometer metrics, without ever affecting the chat path.

**Architecture:** An `InsightsAdvisor` (call + stream) opens a `TurnRecorder` and stores it on the
outermost `ChatClient` observation context. An `ObservationHandler` attaches model calls, tool
calls and vector-store queries to that recorder by walking the observation parent chain. On turn
end, the advisor builds an immutable `ConversationTurn`, publishes metrics, and hands it to a
bounded async writer that saves it in an `InsightsEventStore` (in-memory in this plan).

**Tech Stack:** Java 21, Gradle (Groovy DSL), Spring Boot 4.1.1, Spring AI 2.0.1 (BOM),
Micrometer, JUnit 5, AssertJ, Reactor Test.

**Spec:** `../../design.md` (sections 3, 5, 6, 7, 8.1–8.6, 9). Read it before starting.

**Plan series:** 1 Core capture (this) · 2 MongoDB store + multi-instance · 3 Dashboard + feedback ·
4 Weekly report, Bedrock KB catalog, OTel naming, Grafana assets, demo app, Maven Central release.

## Global Constraints

- Java 21 toolchain; Spring Boot 4.1.1; Spring AI BOM 2.0.1. No Lombok — use records.
- Group / root package: `io.github.springaiinsights` (designer's call; rename before the first release if needed).
- Property prefix `ai-insights` (never `spring.*`).
- Modules: `spring-ai-insights-core`, `spring-ai-insights-autoconfigure`, `spring-ai-insights-starter`.
- Anti-goal: an insights failure (resolver, store, metrics, bug) must **never** fail or slow the
  chat call. Every insights code path in the advisor and handler is wrapped and counted in
  `ai.insights.internal.errors`.
- No user ID, conversation ID or turn ID as a metric tag, ever. Tenant tag only if
  `ai-insights.metrics.tenant-tag=true`.
- Message content stored only when `ai-insights.capture-content=true` (default `false`).
- User IDs pseudonymised by default with HMAC-SHA256 (lower-case hex, 64 chars).
- Prices are per **1 000 000** tokens, `BigDecimal`, scale 10, `RoundingMode.HALF_UP`.
- Local build note: if Gradle fails with `Unsupported class file major version 69`, run it with
  `-Dorg.gradle.java.home=$HOME/.sdkman/candidates/java/21.0.11-amzn`.

## Review Focus

1. **Store down or slow** → chat still answers normally; the event is counted as a store error or
   dropped. *(Task 5 `writerSurvivesStoreFailure`, Task 9 `chatWorksWhenStoreThrows`)*
2. **Client cancels a stream midway** → the turn is still recorded with outcome `CANCELLED` and
   the tokens seen so far. *(Task 8 `streamCancelledRecordsCancelledTurn`)*
3. **Concurrent turns on the same app** → tool calls and model calls never leak between turns.
   *(Task 9 `concurrentTurnsDoNotMixToolCalls`)*
4. **Provider returns no usage / null token counts** → zero tokens, cost computed on zeros, no
   NPE. *(Task 6 `nullUsageCountsAsZero`)*
5. **No Spring Security on the classpath / anonymous request** → `userId` null, turn recorded.
   *(Task 9 `anonymousTurnHasNullUser`)*

```java
    public int getOrder();     // Ordered.HIGHEST_PRECEDENCE + 100 — must stay outside chat memory
                               // (Advisor.DEFAULT_CHAT_MEMORY_PRECEDENCE_ORDER = +200) and
                               // ToolCallingAdvisor.DEFAULT_ORDER (+300), so one turn spans the tool loop
}
```
Behaviour (call and stream share one private `open(...)` / `close(...)`):
1. Find the advisor's own observation: call → `observations.getCurrentObservation()`; stream →
   `Flux.deferContextual` reading `ObservationThreadLocalAccessor.KEY` from the Reactor context
   (fallback: current observation). Walk up to the nearest `ChatClientObservationContext`.
2. If `TurnRecorders.outermost(thatContext)` already exists → **nested call**: pass through untouched.
3. Otherwise open a turn: `turnId` = random UUID; identity = resolver (then pseudonymise
   `userId` if a pseudonymiser is set); conversation ID from `request.context().get(ChatMemory.CONVERSATION_ID)`,
   else a random UUID with `conversationIdMissing=true`; attributes from context keys starting with
   `InsightsContextKeys.ATTRIBUTE_PREFIX` (prefix stripped, `toString()` values); attach the recorder
   to the `ChatClientObservationContext` (if none found, keep it local — uncorrelated mode).
4. Every returned `ChatClientResponse` gets `InsightsContextKeys.TURN_ID` in its context.
5. Stream: `markFirstToken` on the first response with non-empty text; accumulate text when
   `captureContent`; finish reasons from the last response; `doFinally` maps
   `ON_COMPLETE→SUCCESS`, `ON_ERROR→ERROR`, `CANCEL→CANCELLED`.
6. Call: on exception → finish `ERROR` and rethrow the original exception.
7. On finish: if the recorder has no model calls and the response has usage (uncorrelated mode),
   add one model call from the response metadata (provider `"unknown"`). Then
   `metrics.turnRecorded(turn)` and `writer.submit(turn)`.
8. Steps 1–3 and 7 are wrapped: any insights exception → `metrics.internalError()` and the chat
   continues (the request is passed through unchanged).
